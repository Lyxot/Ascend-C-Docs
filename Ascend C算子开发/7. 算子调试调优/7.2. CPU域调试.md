  <h1 class="topictitle1">CPU域调试</h1>
  <div>
   <p>本节介绍CPU域调试的方法：gdb调试、使用printf打印命令打印。</p>
   <p>本节提供的调试方法基于<a href="https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/opdevg/Ascendcopdevg/atlas_ascendc_10_0056.html">Kernel直调</a>章节中的算子程序进行调试，请先完成核函数运行验证章节的学习。</p>
   <div class="note">
    <img src="https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/opdevg/Ascendcopdevg/public_sys-resources/note_3.0-zh-cn.png"><span class="notetitle"> </span>
    <div class="notebody">
     <p>CPU调测过程中，配置日志相关环境变量，可以记录程序的运行过程及异常信息，有助于开发者进行功能调测。</p>
     <p>关于环境变量的使用约束以及详细说明，可参见<a href="https://www.hiascend.com/document/detail/zh/CANNCommunityEdition/82RC1/maintenref/envvar/envref_07_0118.html">日志</a>。</p>
    </div>
   </div>
   <div class="section">
    <h4 class="sectiontitle">gdb调试</h4>
    <p>可使用<strong>gdb</strong>单步调试算子计算精度。由于cpu调测已转为多进程调试，每个核都会拉起独立的子进程，故gdb需要转换成子进程调试的方式。针对<span><term>
       Atlas 推理系列产品
      </term></span><span>、<span><term>
        Atlas 训练系列产品
       </term></span></span>，每个核会拉起1个子进程。针对<span><term>
       Atlas A2 训练系列产品/Atlas 800I A2 推理产品/A200I A2 Box 异构组件
      </term></span>，每个核会拉起3个子进程，1个Cube，2个Vector。</p>
    <ul>
     <li>调试单独一个子进程
      <p><a name="ZH-CN_TOPIC_0000002370254793__zh-cn_topic_0000001457309966_li1379314003611"></a><a name="zh-cn_topic_0000001457309966_li1379314003611"></a>启动gdb，示例中的add_custom_cpu为CPU域的算子可执行文件，参考<a href="https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/opdevg/Ascendcopdevg/atlas_ascendc_10_0056.html#ZH-CN_TOPIC_0000002370175065__section188001652105215">修改并执行一键式编译运行脚本</a>，将一键式编译运行脚本中的run-mode设置成cpu，即可编译生成CPU域的算子可执行文件。</p>
      <div class="p">
       gdb启动后，首先设置跟踪子进程，之后再打断点，就会停留在子进程中，但是这种方式只会停留在遇到断点的第一个子进程中，其余子进程和主进程会继续执行直到退出。涉及到核间同步的算子无法使用这种方法进行调试。
       <pre class="screen">gdb --agrs add_custom_cpu  // 启动gdb，add_custom_cpu为算子可执行文件
(gdb) set follow-fork-mode child</pre>
      </div></li>
     <li>调试多个子进程
      <p><a name="ZH-CN_TOPIC_0000002370254793__zh-cn_topic_0000001457309966_li17465575361"></a><a name="zh-cn_topic_0000001457309966_li17465575361"></a>如果涉及到核间同步，那么需要能同时调试多个子进程。</p>
      <p>在gdb启动后，首先设置调试模式为只调试一个进程，挂起其他进程。设置的命令如下：</p>
      <div class="codecoloring" codetype="ColdFusion">
       <div class="highlight">
        <table class="highlighttable">
         <tbody>
          <tr>
           <td class="linenos">
            <div class="linenodiv">
             <pre><span class="normal">1</span></pre>
            </div></td>
           <td class="code">
            <div>
             <pre><span class="p">(</span><span class="nv">gdb</span><span class="p">)</span> <span class="nv">set</span> <span class="nv">detach</span><span class="o">-</span><span class="nv">on</span><span class="o">-</span><span class="nv">fork</span> <span class="nv">off</span>
</pre>
            </div></td>
          </tr>
         </tbody>
        </table>
       </div>
      </div>
      <p>查看当前调试模式的命令为：</p>
      <div class="codecoloring" codetype="ColdFusion">
       <div class="highlight">
        <table class="highlighttable">
         <tbody>

            <div class="linenodiv">
             <pre><span class="normal">1</span></pre>
            </div></td>
           <td class="code">
            <div>
             <pre><span class="p">(</span><span class="nv">gdb</span><span class="p">)</span> <span class="nv">show</span> <span class="nv">detach</span><span class="o">-</span><span class="nv">on</span><span class="o">-</span><span class="nv">fork</span>
</pre>
            </div></td>
          </tr>
         </tbody>
        </table>
       </div>
      </div>
      <p>中断gdb程序要使用捕捉事件的方式，即gdb程序捕捉fork这一事件并中断。这样在每一次起子进程时就可以中断gdb程序。设置的命令为：</p>
      <div class="codecoloring" codetype="ColdFusion">
       <div class="highlight">
        <table class="highlighttable">
         <tbody>
          <tr>
           <td class="linenos">
            <div class="linenodiv">

            </div></td>
           <td class="code">
            <div>
             <pre><span class="p">(</span><span class="nv">gdb</span><span class="p">)</span> <span class="k">catch</span> <span class="nv">fork</span>
</pre>
            </div></td>
          </tr>
         </tbody>
        </table>
       </div>
      </div>

      <p>执行c后，再次查看info inferiors，可以看到此时第一个子进程已经启动。</p>

  <span class="m">1</span>    <span class="nv">process</span> <span class="m">19613</span>

      <p>请注意，inferior后跟的数字是进程的序号，而不是进程号。</p>
      <p>如果遇到同步阻塞，可以切换回主进程继续生成子进程，然后再切换到新的子进程进行调试，等到同步条件完成后，再切回第一个子进程继续执行。</p></li>
    </ul>
    <p>如下是调试一个单独子进程的命令样例：</p>
    <pre class="screen">gdb --args add_custom_cpu
set follow-fork-mode child
break add_custom.cpp:45
run
list
backtrace
print i
break add_custom.cpp:56
continue
display xLocal
quit</pre>
