# 检测内核调用符方式的Ascend C算子

#### 操作步骤

1. 请参考[内核调用符场景准备](https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/devaids/optool/atlasopdev_16_0040.html#ZH-CN_TOPIC_0000002336189062__li1154375912411)，完成使用前准备。
2. 参考[使用前准备](https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/devaids/optool/atlasopdev_16_0040.html)完成相关环境变量的配置。
3. 构建单算子可执行文件。  
  以Add算子为例，可执行文件的构建命令示例如下：  
  ```bash
  bash run.sh -r npu -v `<soc_version>`
  ```
  一键式编译运行脚本完成后，在工程目录下生成NPU侧可执行文件`<kernel_name>_npu`。
4. 使用msSanitizer检测工具拉起单算子可执行文件（以`add_npu`为例）。  
  - 内存检测执行以下命令，具体参数说明请参考[表2](https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/devaids/optool/atlasopdev_16_0039.html#ZH-CN_TOPIC_0000002336189042__zh-cn_topic_0000001691887174_table716213104506)和[表3](https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/devaids/optool/atlasopdev_16_0039.html#ZH-CN_TOPIC_0000002336189042__zh-cn_topic_0000001691887174_table1796112119339)，内存检测请参考[内存检测示例说明](#ZH-CN_TOPIC_0000002336189118__zh-cn_topic_0000001748881321_section59511855135614)。  
    ```bash
    mssanitizer --tool=memcheck ./add_npu  # 内存检测需指定 --tool=memcheck
    ```
  - 竞争检测执行以下命令，具体参数说明请参考[表2](https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/devaids/optool/atlasopdev_16_0039.html#ZH-CN_TOPIC_0000002336189042__zh-cn_topic_0000001691887174_table716213104506)，竞争检测请参考[竞争检测示例说明](#ZH-CN_TOPIC_0000002336189118__zh-cn_topic_0000001748881321_section15332171054714)。  
    ```bash
    mssanitizer --tool=racecheck ./add_npu  # 竞争检测需指定 --tool=racecheck
    ```
  单算子可执行文件所在路径可配置为绝对路径或相对路径，请根据实际环境配置。

#### 内存检测示例说明

- 在[步骤1](#ZH-CN_TOPIC_0000002336189118__zh-cn_topic_0000001748881321_li81191943134016)之前，需要在Add算子中构造一个非法读写的场景，将DataCopy内存拷贝长度从TILE_LENGTH改为2 * TILE_LENGTH，此时最后一次拷贝会发生内存读写越界。  
  ```cpp
    __aicore__ inline void CopyOut(int32_t progress)
    {
        // deque output tensor from VECOUT queue
        LocalTensor<half> zLocal = outQueueZ.DeQue<half>();
        // copy progress_th tile from local tensor to global tensor
        // 构造非法读写场景
        DataCopy(zGm[progress * TILE_LENGTH], zLocal, 2 * TILE_LENGTH);
        // free output tensor for reuse
        outQueueZ.FreeTensor(zLocal);
    }
  ```
- 根据检测工具输出的报告，可以发现在**add_custom.cpp**的65行对GM存在224字节的非法写操作，与我们构造的异常场景对应。

#### 竞争检测示例说明

- 在[步骤1](#ZH-CN_TOPIC_0000002336189118__zh-cn_topic_0000001748881321_li81191943134016)之前，需要在Add算子中构造一个核间竞争的场景，将DataCopy内存拷贝长度从TILE_LENGTH改为2 * TILE_LENGTH，此时会在GM内存上存在核间竞争。  
  ```cpp
    __aicore__ inline void CopyOut(int32_t progress)
    {
        // deque output tensor from VECOUT queue
        LocalTensor<half> zLocal = outQueueZ.DeQue<half>();
        // copy progress_th tile from local tensor to global tensor
        // 构造核间竞争场景
        DataCopy(zGm[progress * TILE_LENGTH], zLocal, 2 * TILE_LENGTH);
        // free output tensor for reuse
        outQueueZ.FreeTensor(zLocal);
    }
  ```
- 根据检测工具输出的报告，可以发现在**add_kernel.cpp**的65行，AIV的0核和1核存在核间竞争，符合我们构造的异常场景。
