    <h4 class="sectiontitle">功能说明</h4>
    <p id="ZH-CN_TOPIC_0000002370171621__p390041104520">对所有的输入数据求和。归约指令的总体介绍请参考<a href="https://www.hiascend.com/document/detail/zh/CANNCommunityEdition/82RC1/opdevg/Ascendcopdevg/atlas_ascendc_10_0023.html">如何使用归约指令</a>。</p>
    <div class="p" id="ZH-CN_TOPIC_0000002370171621__p6853520201916">
     ReduceSum的相加方式分为两种：
     <ul id="ZH-CN_TOPIC_0000002370171621__ul1691211016414">
      <li id="ZH-CN_TOPIC_0000002370171621__li15667135613613">方式一：同一repeat内先按照二叉树累加、不同repeat的结果也按照二叉树累加。
       <p id="ZH-CN_TOPIC_0000002370171621__p1881410558595"><a name="ZH-CN_TOPIC_0000002370171621__li15667135613613"></a><a name="li15667135613613"></a>假设源操作数为128个half类型的数据[data0,data1,data2...data127]，一个repeat可以计算完，计算过程如下。</p>
       <ol id="ZH-CN_TOPIC_0000002370171621__ol881445555914">
        <li id="ZH-CN_TOPIC_0000002370171621__li178141555205917">data0和data1相加得到data00，data2和data3相加得到data01，...，data124和data125相加得到data62，data126和data127相加得到data63；</li>
        <li id="ZH-CN_TOPIC_0000002370171621__li15814355125916">data00和data01相加得到data000，data02和data03相加得到data001，...，data62和data63相加得到data031；</li>
        <li id="ZH-CN_TOPIC_0000002370171621__li1981415554594">以此类推，得到目的操作数为1个half类型的数据[data]。</li>
       </ol>
       <p id="ZH-CN_TOPIC_0000002370171621__p78144551591">需要注意的是两两相加的计算过程中，计算结果大于65504时结果保存为65504。例如源操作数为[60000,60000,-30000,100]，首先60000+60000溢出，结果为65504，第二步计算-30000+100=-29900，第四步计算65504-29900=35604。</p></li>
      <li id="ZH-CN_TOPIC_0000002370171621__li102977191672">方式二：同一repeat内采用二叉树累加，不同repeat的结果按顺序累加。</li>
     </ul>
    </div>
    <p id="ZH-CN_TOPIC_0000002370171621__p246113074814">不同硬件形态对应的ReduceSum相加方式如下：</p>
    <p id="ZH-CN_TOPIC_0000002370171621__p2049315012719"><span id="ZH-CN_TOPIC_0000002370171621__ph1649310501977"><term id="ZH-CN_TOPIC_0000002370171621__zh-cn_topic_0000002336176798_term71949488213_1">
       Atlas 训练系列产品
      </term></span>采用方式一</p>
    <p id="ZH-CN_TOPIC_0000002370171621__p1549320501577"><span id="ZH-CN_TOPIC_0000002370171621__ph14493350378"><term id="ZH-CN_TOPIC_0000002370171621__zh-cn_topic_0000002336176798_term1964153212227_1">
       Atlas 推理系列产品
      </term>AI Core</span>采用方式一</p>
    <p id="ZH-CN_TOPIC_0000002370171621__p227616451158"><span id="ZH-CN_TOPIC_0000002370171621__ph1527654551517"><term id="ZH-CN_TOPIC_0000002370171621__zh-cn_topic_0000002336176798_term11962195213215_1">

    <h4 class="sectiontitle">约束说明</h4>
    <ul id="ZH-CN_TOPIC_0000002370171621__ul144961427164811">
     <li id="ZH-CN_TOPIC_0000002370171621__li38161226123420">为了节省地址空间，开发者可以定义一个Tensor，供srcLocal、dstLocal、workLocal同时使用（即地址重叠），地址重叠的约束条件如下：
      <ul id="ZH-CN_TOPIC_0000002370171621__ul139621524134813">
       <li id="ZH-CN_TOPIC_0000002370171621__li147013402420">若源操作数与目的操作数之间存在依赖，即第N次迭代的目的操作数是第N+1次的源操作数，这种情况不支持地址重叠。</li>
       <li id="ZH-CN_TOPIC_0000002370171621__li01938365484">srcLocal或者dstLocal与workLocal地址重叠时，workLocal必须满足最小所需空间要求，否则不支持地址重叠。</li>
       <li id="ZH-CN_TOPIC_0000002370171621__li17611124812211">各操作数地址如重叠则要求100%完全重叠，不支持部分重叠。</li>
      </ul></li>
     <li id="ZH-CN_TOPIC_0000002370171621__li976422415398">该接口内部通过软件仿真来实现ReduceSum功能，某些场景下，性能可能不及直接使用硬件指令实现的<a href="https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/API/ascendcopapi/atlasascendc_api_07_0084.html">BlockReduceSum</a>和<a href="https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/API/ascendcopapi/atlasascendc_api_07_0081.html">WholeReduceSum</a>接口。针对不同场景合理使用归约指令可以带来性能提升，相关介绍请参考<a href="https://www.hiascend.com/document/detail/zh/CANNCommunityEdition/82RC1/opdevg/ascendcbestP/atlas_ascendc_best_practices_10_0031.html">针对不同场景合理使用归约指令</a>，具体样例请参考<span id="ZH-CN_TOPIC_0000002370171621__ph75302464319"><a href="https://gitee.com/ascend/samples/tree/v1.5-8.2.RC1/operator/ascendc/0_introduction/14_reduce_frameworklaunch/ReduceCustom" target="_blank" rel="noopener noreferrer">ReduceCustom</a></span>。</li>
