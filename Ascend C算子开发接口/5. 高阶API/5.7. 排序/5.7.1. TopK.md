   <div class="section">
    <h4 class="sectiontitle">功能说明</h4>
    <p>获取最后一个维度的前k个最大值或最小值及其对应的索引。</p>
    <p>如果输入是向量，则在向量中找到前k个最大值或最小值及其对应的索引；如果输入是矩阵，则沿最后一个维度计算每行中前k个最大值或最小值及其对应的索引。<strong>本接口最多支持输入为二维数据，不支持更高维度的输入。</strong></p>
    <p>如下图所示，对shape为(4, 32)的二维矩阵进行排序，k设置为1，输出结果为[[32] [32] [32] [32]]。</p>
    <p><img class="eddx" src="https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/API/ascendcopapi/figure/zh-cn_image_0000002336335282.png"></p>
    <ul>
     <li><strong>必备概念</strong>
      <p>基于如上样例，我们引入一些必备概念：行数称之为<strong>外轴长度（outter）</strong>，每行实际的元素个数称之为<strong>内轴的实际长度（n）</strong>。本接口要求输入的内轴长度为32的整数倍，所以当n不是32的整数倍时，需要开发者将其向上补齐到32的整数倍，补齐后的长度称之为<strong>内轴长度（inner）</strong>。比如，如下的样例中，每行的实际长度n为31，不是32的整数倍，向上补齐后得到inner为32，图中的padding代表补齐操作。n和inner的关系如下：当n是32的整数倍时，inner=n；否则，inner &gt; n。</p>
      <p><img class="eddx" src="https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/API/ascendcopapi/figure/zh-cn_image_0000002336335294.png"></p></li>
     <li><strong>接口模式</strong>
      <p>本接口支持两种模式：<strong>Normal模式</strong>和<strong>Small模式</strong>。Normal模式是通用模式；Small模式是为内轴长度固定为32（单位：元素个数）的场景提供的高性能模式。因为Small模式inner固定为32，可以进行更有针对性的处理，所以相关的约束较少，性能较高。内轴长度inner为32时建议使用Small模式。</p></li>
     <li><strong>附加功能</strong>：本接口支持开发者指定某些行的排序是无效排序。通过传入finishLocal参数值来控制，finishLocal对应行的值为true时，表示该行排序无效，此时排序后输出的dstIndexLocal的k个索引值会全部被置为无效索引n。
      <p><img class="imgResize" src="https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/API/ascendcopapi/figure/zh-cn_image_0000002336335286.png" title="点击放大"></p></li>
    </ul>
   </div>

    <h4 class="sectiontitle">实现原理</h4>
    <p>以float类型，ND格式，shape为[outter, inner]的输入Tensor为例，描述TopK高阶API内部算法框图，如下图所示。</p>
    <div class="fignone">
     <span class="figcap"><b>图1 </b>TopK算法框图</span>
     <br><img class="imgResize" src="https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/API/ascendcopapi/figure/zh-cn_image_0000002336335298.png" title="点击放大">
    </div>
    <p>根据TopKMode不同的模式选择，可分为两个分支。</p>
    <ul>
     <li>计算TopK NORMAL模式，过程如下：
      <ol>
       <li>模板参数isInitIndex为false，需生成0到inner - 1的索引；
        <p><a name="ZH-CN_TOPIC_0000002336174002__li7591183920612"></a><a name="li7591183920612"></a><span><term>
           Atlas A3 训练系列产品/Atlas A3 推理系列产品
          </term></span>采用方式二。</p>
        <p><span><term>
           Atlas A2 训练系列产品/Atlas 800I A2 推理产品/A200I A2 Box 异构组件
          </term></span>采用方式二。</p>
        <p><span><term>
           Atlas 推理系列产品
          </term></span>采用方式二。</p>
        <ul>
         <li>方式一：使用CreateVecIndex生成0到inner - 1的索引。</li>
         <li>方式二：使用ArithProgression生成0到inner - 1的索引。</li>
        </ul></li>
       <li>isLargest参数为false，由于Sort32指令默认为降序排序，则给数据乘以-1；</li>
       <li>对输入数据完成全排序。
        <p><a name="ZH-CN_TOPIC_0000002336174002__li231511182179"></a><a name="li231511182179"></a><span><term>
           Atlas A3 训练系列产品/Atlas A3 推理系列产品
          </term></span>采用方式二。</p>
        <p><span><term>
           Atlas A2 训练系列产品/Atlas 800I A2 推理产品/A200I A2 Box 异构组件
          </term></span>采用方式二。</p>
        <p><span><term>
           Atlas 推理系列产品
          </term></span>采用方式二。</p>
        <ul>
         <li>方式一：
          <p><a name="ZH-CN_TOPIC_0000002336174002__li12916164014211"></a><a name="li12916164014211"></a>使用高阶API Sort对数据完成全排序。</p></li>
         <li>方式二：
          <ol type="a">
           <li>使用Sort32对数据排序，保证每32个数据是有序的。</li>
           <li>使用MrgSort指令对所有的已排序数据块归并排序。</li>
          </ol></li>
        </ul></li>
       <li>使用GatherMask指令提取前k个数据和索引；</li>
       <li>finishLocal[i]为true时，则更新该行对应的排序结果为无效索引n；</li>
       <li>isLargest参数为false，则给数据乘以-1还原数据。</li>
      </ol>
      <p>注意：<span><term>
         Atlas 推理系列产品
        </term></span>上使用ProposalConcat基础API将data和index组合起来后，再使用RpSort16基础API对数据排序；使用MrgSort4进行归并；使用ProposalExtract基础API提取data和index。</p></li>
    </ul>
    <ul>
     <li>计算TopK SMALL模式，过程如下：
      <ol>
       <li>模板参数isInitIndex为false，需生成0到inner - 1的索引，并使用Copy指令将数据复制为outter条；
        <p><a name="ZH-CN_TOPIC_0000002336174002__li15372142163311"></a><a name="li15372142163311"></a><span><term>
           Atlas A3 训练系列产品/Atlas A3 推理系列产品
          </term></span>采用方式二。</p>
        <p><span><term>
           Atlas A2 训练系列产品/Atlas 800I A2 推理产品/A200I A2 Box 异构组件
          </term></span>采用方式二。</p>
        <p><span><term>
           Atlas 推理系列产品
          </term></span>采用方式二。</p>
        <ul>
         <li>方式一：使用CreateVecIndex生成0到inner - 1的索引。</li>
         <li>方式二：使用ArithProgression生成0到inner - 1的索引。</li>
        </ul></li>
       <li>isLargest参数为false，由于Sort32指令默认为降序排序，则给输入数据乘以-1；</li>
       <li>使用Sort32对数据排序；</li>
       <li>使用GatherMask指令提取前k个数据和索引；</li>
       <li>isLargest参数为false，则给输入数据乘以-1还原数据。</li>
      </ol>
      <p>注意：<span><term>
         Atlas 推理系列产品
        </term></span>上使用ProposalConcat基础API将data和index组合起来后，再使用RpSort16基础API对数据排序；由于small模式下inner为32，RpSort16排序后为每16个数据有序，因此在步骤3和步骤4之间，使用MrgSort4基础API进行一次归并排序。</p></li>
    </ul>

   <p>由于该接口的内部实现中涉及复杂的逻辑计算，需要额外的临时空间来存储计算过程中的中间变量。临时空间支持<strong>API</strong><strong>接口申请</strong>和开发者<strong>通过tmpLocal入参传入</strong>两种方式。</p>
   <ul>
    <li>API接口内部申请临时空间，开发者无需申请，但是需要预留临时空间的大小。</li>
   </ul>
   <ul>
    <li>通过tmpLocal入参传入，使用该tensor作为临时空间进行处理，API接口内部不再申请。该方式开发者可以自行管理tmpLocal内存空间，并在接口调用完成后，复用该部分内存，内存不会反复申请释放，灵活性较高，内存利用率也较高。临时空间大小tmpLocal的BufferSize的获取方式如下：通过<a href="https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/82RC1/API/ascendcopapi/atlasascendc_api_07_0837.html">TopK Tiling</a>中提供的GetTopKMaxMinTmpSize接口获取所需最大和最小临时空间大小。</li>
   </ul>
