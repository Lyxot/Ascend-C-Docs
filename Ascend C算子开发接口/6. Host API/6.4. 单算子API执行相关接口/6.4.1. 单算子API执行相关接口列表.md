# 单算子API执行相关接口列表

#### 整体说明

无论是基于Ascend C自定义的算子还是CANN提供的内置算子，都可以通过**aclnn前缀API**（简称aclnn接口）形式调用算子，这种方式称为“**单算子API执行**”。该方法简单且灵活，更便于用户进行AI业务开发与应用。

> **说明：**
> - aclnn前缀API：简称aclnn接口，属于[Level2层接口](#ZH-CN_TOPIC_0000002370171629__zh-cn_topic_0000001917744184_li572474119382)，本质是一类C语言API，调用算子时无需提供IR（Intermediate Representation）定义。
> - 内置算子：CANN的算子加速库（Ascend Operator Library，简称AOL），包含一系列高性能算子和aclnn接口，用户可直接使用，无需自定义，详细介绍请参考《[AOL算子加速库接口参考](https://www.hiascend.com/document/detail/zh/CANNCommunityEdition/82RC1/apiref/aolapi/operatorlist_00001.html)》。
> - “**单算子API执行**”是一种单算子调用方式，其调用流程和其他调用方式介绍请参考“[单算子调用流程](https://www.hiascend.com/document/detail/zh/CANNCommunityEdition/82RC1/appdevg/acldevg/aclcppdevg_000017.html)”。

为实现API形式直调算子，本章提供了单算子API执行依赖的底层框架接口和基础核函数接口（即[Level0层接口](#ZH-CN_TOPIC_0000002370171629__zh-cn_topic_0000001917744184_li1543255153717)），详细阐述了接口的原型、功能、参数说明、约束与限制、调用示例等，指导开发者快速掌握接口含义和使用方法。

- 框架能力接口：提供实现aclnn前缀接口相关的基础能力接口，比如算子执行器（opExecutor）处理、数据类型/格式/shape等操作，具体如[表1](#ZH-CN_TOPIC_0000002370171629__table2070319561334)所示；此外还包括常用类和宏，具体参见[表2](#ZH-CN_TOPIC_0000002370171629__table370875616310)、[表3](#ZH-CN_TOPIC_0000002370171629__table2712056035)。
- 基础核函数接口：提供实现aclnn前缀接口的基础核函数接口，比如Tensor数据类型转换、shape重构等，具体如[表4](#ZH-CN_TOPIC_0000002370171629__table177150561835)所示。

使用上述接口时，注意请根据实际情况include依赖的头文件，头文件路径为${INSTALL_DIR}/include目录，其中${INSTALL_DIR}请替换为CANN软件安装后文件存储路径。若安装的Ascend-cann-toolkit软件包，以root安装举例，则安装后文件存储路径为：/usr/local/Ascend/ascend-toolkit/latest。

为更好指导开发者应用本章接口，**端到端的接口调用示例**可参考Gitee **cann-ops-adv仓**，该仓开放了融合算子实现的源代码，单击[Link](https://gitee.com/ascend/cann-ops-adv)访问“/src/transformer/${OpType}/ophost/”获取不同算子源码，${OpType}表示算子类型。如果您需要对算子Host侧API实现进行**定制化修改**，建议先熟悉本章接口。

#### 基本概念

- <a name="ZH-CN_TOPIC_0000002370171629__zh-cn_topic_0000001917744184_li1543255153717"></a><a name="zh-cn_topic_0000001917744184_li1543255153717"></a>**Level0层接口**  
  简称L0接口，表示调用单Kernel的Host侧API，提供了细颗粒API（单Kernel下发）和算子API开发的基础结构体（如Tensor定义等）和公共基础能力（如workspace复用、引擎调度等），上层应用或者L2接口可通过L0接口的快速组装实现高性能计算。  
  L0接口返回值类型是Tensor的类型结构，如aclTensor*、std::tuple<aclTensor*, aclTensor*>、aclTensorList*，最后一个参数固定为aclOpExecutor *executor，类型与名称均不可变，示例如下：  
```cpp
aclTensor* AddNd(aclTensor *x1, aclTensor *x2, aclOpExecutor *executor)
```
  L0接口命名空间为“namespace l0op”，接口名为“${op_type}${format}${dtype}”，其中${op_type}为算子名，${format}为算子输入/输出数据格式，${dtype}为算子输入/输出数据类型（对于非常规的输入/输出数据类型，需带上数据类型匹配关系）。调用示例如下：  
```cpp
l0op::AddNd                               //Add算子输入均按ND计算
l0op::MatMulNdFp162Fp32                   //MatMul算子输入输出均按ND格式计算，并且2代表“To”，表示输入fp16、输出fp32
l0op::MatMulNzFp162Fp16                   //MatMul算子输入输出均按NZ格式计算，并且2代表“To”，表示输入与输出都是fp16
```
- <a name="ZH-CN_TOPIC_0000002370171629__zh-cn_topic_0000001917744184_li572474119382"></a><a name="zh-cn_topic_0000001917744184_li572474119382"></a>**Level2层接口**  
  简称L2接口，是对L0接口的高层级封装（内部通过调用单个或多个L0接口实现更灵活功能），表示更上层的Host侧API。该类接口提供单算子直调方式，屏蔽了算子内部实现逻辑，用户直接调用L2接口即可实现调用算子。  
  L2接口返回值类型是aclnnStatus，一般包括获取workspaceSize和算子执行“两段式接口”：
```cpp
aclnnStatus aclnnXxxGetWorkspaceSize(const aclTensor *src, ..., aclTensor *out, ..., uint64_t *workspaceSize, aclOpExecutor **executor);
aclnnStatus aclnnXxx(void *workspace, uint64_t workspaceSize, aclOpExecutor *executor, aclrtStream stream);
```
  1. aclnnXxxGetWorkspaceSize最后两个参数固定为(uint64_t *workspaceSize, aclOpExecutor **executor)，名称和类型均不可变。  
  2. aclnnXxx接口参数固定为(void *workspace, uint64_t workspaceSize, aclOpExecutor *executor, aclrtStream stream)。  
  其中aclnnXxxGetWorkspaceSize为第一段接口，主要用于计算本次API调用过程中需要多少workspace内存，获取到本次计算所需的workspaceSize后，按照workspaceSize申请NPU内存，然后调用第二段接口aclnnXxx执行计算。“Xxx”表示对应的算子类型，如Add算子。

> **说明：**
> - workspace是指除输入/输出外，API在昇腾AI处理器上完成计算所需要的临时内存。
> - 二阶段接口aclnnXxx(...)不能重复调用，如下调用方式会出现异常：
> ```cpp
> aclnnXxxGetWorkspaceSize(...)
> aclnnXxx(...)
> aclnnXxx(...)
> ```
